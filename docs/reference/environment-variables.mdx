MCP Hub uses environment variables for all runtime configuration. Copy `.env.example` to `.env` in the project root and set the values before starting the app. This page documents every available variable.

## .env.example

Use this as a starting point. Copy it to `.env` and replace each placeholder with a real value before running the app.

```bash
# Core runtime
NODE_ENV=development
PORT=3000
EXPO_PORT=8081

# Database
DATABASE_URL=mysql://user:password@localhost:3306/mcp_hub

# Auth / sessions
COOKIE_SECRET=change-me
JWT_SECRET=change-me

# MCP and external integrations
MCP_SERVER_URL=http://localhost:3001
OPENAI_API_KEY=
```

<Warning>
  Never commit your `.env` file. Ensure it is listed in your `.gitignore` before your first `git add`.
</Warning>

## Required Variables

These three variables must be set before MCP Hub will start. The app will exit with an error if any of them are missing or left at their placeholder values.

| Variable | Description | Example |
|---|---|---|
| `DATABASE_URL` | MySQL connection string. Format: `mysql://user:password@host:port/database`. Use a dedicated, least-privileged application user — not `root`. | `mysql://mcp_app:<password>@localhost:3306/mcp_hub` |
| `COOKIE_SECRET` | Secret for signing session cookies. Use a cryptographically random string of **at least 32 characters**. Must stay constant between restarts — changing it invalidates all active sessions. | *(generated — see below)* |
| `JWT_SECRET` | Secret for signing JWT tokens. Use a **different** random string of at least 32 characters. | *(generated — see below)* |

## Optional Variables

These variables have safe defaults for local development. Override them in `.env` when you need a different port, a remote MCP server, or AI features.

| Variable | Default | Description |
|---|---|---|
| `NODE_ENV` | `development` | Set to `production` for deployments. Affects logging verbosity and security hardening (e.g., secure cookies). |
| `PORT` | `3000` | Port for the backend API server. Change this if port 3000 is already in use on your machine. |
| `EXPO_PORT` | `8081` | Port for the Expo / web frontend served by Metro. Change this if port 8081 conflicts with another process. |
| `MCP_SERVER_URL` | `http://localhost:3001` | Default MCP server URL used as a starting point when you add your first server. You can override this per-server inside the app. |
| `OPENAI_API_KEY` | *(empty)* | OpenAI API key for AI-powered features. Leave blank to disable AI features entirely — all other functionality continues to work without it. |

## Generating Secure Secrets

Generate cryptographically random values for `COOKIE_SECRET` and `JWT_SECRET` using the Node.js built-in `crypto` module. Run the command twice — once for each secret — and paste the two outputs into your `.env`.

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

<Tip>
  Run this command twice and use a **different output** for `COOKIE_SECRET` and `JWT_SECRET`. Reusing the same secret for both reduces the security of your sessions and tokens.
</Tip>

Your `.env` should look like this after substitution (use your own generated values — do not copy these):

```bash
COOKIE_SECRET=<paste-64-char-hex-output-here>
JWT_SECRET=<paste-different-64-char-hex-output-here>
```

<Warning>
  Treat these values as production secrets. Never commit them to version control, share them in chat, or paste them into bug reports. If a secret is exposed, rotate it immediately and restart the app — all existing sessions and JWTs will be invalidated.
</Warning>

## Database URL Format

`DATABASE_URL` follows the standard connection string format used by Prisma and most MySQL clients:

```
mysql://[user]:[password]@[host]:[port]/[database]
```

Common examples:

```bash
# Local MySQL (default install)
DATABASE_URL=mysql://root:password@localhost:3306/mcp_hub

# MySQL running in Docker
DATABASE_URL=mysql://mcp_user:mcp_pass@127.0.0.1:3306/mcp_hub

# PlanetScale (mysql2 compatible — append ?ssl={"rejectUnauthorized":true})
DATABASE_URL=mysql://abc123:pscale_pw_xxxx@aws.connect.psdb.cloud/mcp_hub?ssl={"rejectUnauthorized":true}

# TiDB Serverless
DATABASE_URL=mysql://root:<password>@gateway01.<region>.prod.aws.tidbcloud.com:4000/mcp_hub?ssl={"rejectUnauthorized":true}
```

<Note>
  If your password contains special characters (e.g., `@`, `/`, `:`), percent-encode them. For example, `p@ss/word` becomes `p%40ss%2Fword`.
</Note>
