MCP Hub persists log messages from each server connection. Use the logs endpoint to query connection logs for debugging, auditing, or monitoring purposes. You can filter by severity level and time range, and adjust the verbosity of log capture at any time without restarting the connection.

## Query persisted logs

**GET /api/connections/\{connectionId\}/logs**

Retrieve log entries for a specific connection. Apply filters to focus on the severity level and time window most relevant to your investigation.

### Query parameters

<ParamField query="level" type="string">
  Return only log entries at or above this severity level. Accepted values: `debug`, `info`, `warn`, `error`, `fatal`. For example, specifying `warn` returns `warn`, `error`, and `fatal` entries but omits `debug` and `info`.
</ParamField>

<ParamField query="since" type="string">
  Return only log entries recorded after this timestamp. Must be a valid ISO 8601 datetime string, e.g. `2025-01-15T10:00:00Z`.
</ParamField>

<ParamField query="until" type="string">
  Return only log entries recorded before this timestamp. Must be a valid ISO 8601 datetime string, e.g. `2025-01-15T11:00:00Z`.
</ParamField>

<ParamField query="limit" type="integer" default="100">
  Maximum number of log entries to return in a single response.
</ParamField>

### Response example

The endpoint returns a JSON array of `LogEntry` objects. Each entry contains `id`, `timestamp`, `level`, `message`, and an optional `metadata` object.

```json
[
  {
    "id": "a1b2c3d4-0000-4abc-8000-000000000001",
    "timestamp": "2025-01-15T10:30:00Z",
    "level": "error",
    "message": "Tool call timed out after 60000ms",
    "metadata": {
      "toolName": "slow_operation",
      "connectionId": "conn_01h..."
    }
  }
]
```

## Set the log verbosity level

**POST /api/connections/\{connectionId\}/logging/level**

Control how much detail MCP Hub captures for a connection by setting its active log level. Changes take effect immediately for all subsequent log output from that connection.

### Request body

```json
{ "level": "debug" }
```

Valid levels in descending order of verbosity: `debug` > `info` > `warn` > `error` > `fatal`. Setting a lower verbosity level (e.g. `debug`) captures all log messages, including those at higher levels. Setting a higher level (e.g. `error`) captures only `error` and `fatal` messages.

<Tip>
  Set the log level to `debug` temporarily when troubleshooting a failing tool call, then switch back to `info` once you have the information you need. This keeps log volume manageable during normal operation.
</Tip>
