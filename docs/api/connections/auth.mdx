MCP Hub supports multiple authentication modes for server connections: OAuth2, bearer tokens, and secret environment variables. Use these endpoints to manage the full auth lifecycle for a connection — from initiating a login flow to refreshing expired tokens and attaching runtime secrets.

---

## Start Auth Flow

```http
POST /api/connections/{connectionId}/auth/start
```

Initiates an authentication flow for the connection. For `oauth2` connections, MCP Hub generates an authorization URL that you redirect your user to. For `bearer` mode, use this endpoint to register the token with the connection.

**Request:**

```json
{
  "strategy": "oauth2",
  "scopes": ["repo", "read:user"],
  "resourceUri": "https://github-mcp.example.com/mcp"
}
```

<ParamField body="strategy" type="string" required>
  The authentication strategy to use. Accepted values: `oauth2`, `bearer`, `none`.
</ParamField>

<ParamField body="scopes" type="array">
  Optional list of OAuth2 scopes to request. Only applicable when `strategy` is `oauth2`.
</ParamField>

<ParamField body="resourceUri" type="string">
  Optional resource URI hint passed to the authorization server. Only applicable when `strategy` is `oauth2`.
</ParamField>

**Response:**

```json
{
  "authUrl": "https://github.com/login/oauth/authorize?client_id=...&state=abc123",
  "state": "abc123"
}
```

<ResponseField name="authUrl" type="string (uri)">
  The URL to redirect your user to in order to complete the OAuth2 authorization flow.
</ResponseField>

<ResponseField name="state" type="string">
  A CSRF state token generated by MCP Hub for this auth flow.
</ResponseField>

Store the `state` value **server-side** (for example, in the user's session) and compare it for exact equality when the OAuth2 provider redirects back. Do not rely on a `state` value echoed from a query string or `localStorage` alone — that defeats CSRF protection.

<Warning>
  Your registered OAuth2 callback (redirect) URL **must use HTTPS in production** and must exactly match the URI registered with the authorization server. `http://` callbacks are only acceptable for `localhost` during local development. Avoid using wildcards or open redirects in the registered URL — these allow an attacker to intercept the authorization code.
</Warning>

<Note>
  After the user completes the OAuth2 flow and your callback URL receives the authorization code, MCP Hub handles the token exchange automatically. Poll `GET /api/connections/{connectionId}/auth/status` to confirm authentication completed successfully. Access and refresh tokens are stored encrypted at rest by MCP Hub and are never returned to the client over the API.
</Note>

<Warning>
  **Callback URL requirements.**

  - Register an `https://` redirect URL with the OAuth provider for any non-localhost deployment.
  - Make sure the registered URL is an **exact match** — including scheme, host, port, and trailing slash.
  - Avoid open redirects, wildcard redirect URIs, and `http://` callbacks. Each one enables token interception.
</Warning>

## Get Auth Status

```http
GET /api/connections/{connectionId}/auth/status
```

Returns the current authentication state for the connection, including whether a valid token exists, the authenticated user identity, token expiry, and granted scopes.

```json
{
  "authenticated": true,
  "userId": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "expiresAt": "2025-06-01T00:00:00Z",
  "scopes": ["repo", "read:user"]
}
```

| Field | Description |
|---|---|
| `authenticated` | `true` if a valid, non-expired token is present |
| `userId` | UUID of the authenticated user as provided by the authorization server, or `null` |
| `expiresAt` | ISO 8601 timestamp when the token expires, or `null` for non-expiring tokens |
| `scopes` | Array of OAuth2 scopes granted, or an empty array for non-OAuth2 modes |

## Refresh Token

```http
POST /api/connections/{connectionId}/auth/refresh
```

Refreshes an expired or near-expiry OAuth2 token using the stored refresh token. No request body is required. MCP Hub performs the token exchange in the background and updates the stored credentials.

Returns `200 OK` with the updated `AuthStatus` on success:

```json
{
  "authenticated": true,
  "userId": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "expiresAt": "2025-07-01T00:00:00Z",
  "scopes": ["repo", "read:user"]
}
```

<Warning>
  If no refresh token is available — for example, because the original OAuth2 grant did not include `offline_access` — this endpoint returns `400 Bad Request`. In that case, restart the auth flow with `/auth/start`.
</Warning>

## Remove Auth State

```http
DELETE /api/connections/{connectionId}/auth
```

Removes all stored authentication state and tokens for the connection. After this call, the connection's `authState` returns to `unauthenticated`. The connection record itself is not deleted.

Returns `204 No Content` on success.

## Attach Secrets

```http
POST /api/connections/{connectionId}/secrets
```

Attaches secret references and plain environment variables to the connection. MCP Hub injects these into the server process environment at startup for connections using `stdio` transport and `secret_env` auth mode.

**Request:**

```json
{
  "secretRefs": ["my-vault-secret-name"],
  "envVars": {
    "GITHUB_TOKEN": "<your-github-token>",
    "API_KEY": "<your-api-key>"
  }
}
```

<ParamField body="secretRefs" type="array">
  An optional list of secret reference names to resolve and inject. MCP Hub looks up each entry in the configured secrets store. Prefer `secretRefs` over `envVars` whenever your secret already lives in a vault — the plain-text value never traverses this API.
</ParamField>

<ParamField body="envVars" type="object">
  An optional map of environment variable names to plain-text values. These are stored encrypted at rest. Submitting a key that already exists overwrites the previous value.
</ParamField>

<Warning>
  **Handling secret values.**

  - Only call this endpoint over HTTPS — values in `envVars` are sent as plain text in the request body.
  - Do not log request bodies or include them in error reports. For production credentials, prefer `secretRefs` (vault lookup) over `envVars` so the raw value never travels through this API.
  - Grant the resolving identity (such as an IAM role) **read-only access to only the specific secret paths it needs** — avoid wildcard policies like `secretsmanager:GetSecretValue` on `*`.
  - Use **least-privilege** tokens. Scope `GITHUB_TOKEN` to the specific repos and permissions the MCP server needs, and avoid full `repo` or `admin` scopes. Use scoped or project-restricted API keys for third-party services.
  - Rotate any secret that may have leaked through shell history, screenshots, or commit history. Provider-side revocation is the only guaranteed remediation.
</Warning>

Returns `200 OK` on success:

```json
{
  "message": "Secrets attached"
}
```

<Note>
  Secrets are only injected when MCP Hub spawns the stdio process. If the connection is already running, disconnect and reconnect to apply updated secrets. Rotate any secret that may have been exposed in logs, screenshots, or shared `.env` files immediately.
</Note>
